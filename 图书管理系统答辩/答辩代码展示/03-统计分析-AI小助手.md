# 03 统计分析、AI 小助手展示

## 一、模块定位

本模块面向管理员提供库存统计和分类分析，同时为管理员和读者提供不同的 AI 能力：管理员获取图书馆运营建议，读者获取个性化图书推荐。

核心源码：

- 前端页面：`frontend/src/views/Statistics.vue`、`frontend/src/views/AI.vue`
- 统计接口：`src/main/java/com/library/controller/BookController.java`
- AI 接口：`src/main/java/com/library/controller/AIController.java`
- AI 业务：`src/main/java/com/library/service/impl/AIServiceImpl.java`
- 模型客户端：`src/main/java/com/library/common/util/DeepSeekClient.java`
- 统计 SQL：`src/main/resources/mapper/BookMapper.xml`

## 二、统计分析

### 1. 后端统计接口

文件：`src/main/java/com/library/controller/BookController.java`

```java
@GetMapping("/stats")
@RequireRole(RoleConstant.ADMIN)
public ApiResult<List<Map<String, Object>>> stats() {
    if (UserContext.get() == null
            || !RoleConstant.ADMIN.equals(UserContext.get().getRole())) {
        throw new BusinessException("仅管理员可以查看统计分析");
    }
    return ApiResult.success(service.stats());
}
```

统计接口明确限制为管理员，避免普通读者看到内部库存和运营数据。

### 2. 按分类聚合库存

文件：`src/main/resources/mapper/BookMapper.xml`

```xml
<select id="categoryStats" resultType="map">
  SELECT c.id AS categoryId,
         c.name AS categoryName,
         COUNT(b.id) AS bookCount,
         COALESCE(SUM(b.total_stock), 0) AS totalStock,
         COALESCE(SUM(b.available_stock), 0) AS availableStock
  FROM category c
  LEFT JOIN book b ON b.category_id = c.id
  GROUP BY c.id, c.name
  ORDER BY bookCount DESC
</select>
```

使用 `LEFT JOIN` 可以保留没有图书的分类；`COALESCE` 将空聚合结果转为 0，避免前端出现空值。

### 3. 前端计算统计指标

文件：`frontend/src/views/Statistics.vue`

```javascript
function availability(row) {
  const total = Number(row.totalStock || 0)
  return total
    ? `${Math.round(Number(row.availableStock || 0) * 100 / total)}%`
    : '0%'
}

async function load() {
  const response = await http.get('/books/stats')
  rows.value = response.data || []
  totals.books = rows.value.reduce(
    (sum, item) => sum + Number(item.bookCount || 0), 0)
  totals.stock = rows.value.reduce(
    (sum, item) => sum + Number(item.totalStock || 0), 0)
  totals.available = rows.value.reduce(
    (sum, item) => sum + Number(item.availableStock || 0), 0)
}
```

后端负责聚合原始数据，前端负责展示总量和可借比例，职责清晰且页面刷新时会重新获取最新库存数据。

## 三、AI 小助手功能

### 1. 前端根据角色切换场景

文件：`frontend/src/views/AI.vue`

```javascript
const isAdmin = computed(() =>
  JSON.parse(localStorage.getItem('library_user') || '{}').role === 'ADMIN'
)

async function ask() {
  if (!prompt.value) return
  loading.value = true
  try {
    const path = isAdmin.value ? '/ai/advice' : '/ai/recommend'
    const response = await http.post(path, prompt.value, {
      headers: { 'Content-Type': 'text/plain' }
    })
    if (response.code !== 200) throw new Error(response.message)
    answer.value = response.data
  } finally {
    loading.value = false
  }
}
```

管理员和读者共用一个页面，但根据角色请求不同接口：

- 管理员：`POST /api/ai/advice`，生成运营建议。
- 读者：`POST /api/ai/recommend`，生成图书推荐。

### 2. 后端接口权限

文件：`src/main/java/com/library/controller/AIController.java`

```java
@RestController
@RequestMapping("/api/ai")
public class AIController {
    @PostMapping("/recommend")
    @RequireRole(RoleConstant.READER)
    public ApiResult<String> recommend(@RequestBody String prompt) {
        return ApiResult.success(service.readerRecommend(prompt));
    }

    @PostMapping("/advice")
    @RequireRole(RoleConstant.ADMIN)
    public ApiResult<String> advice(@RequestBody String prompt) {
        return ApiResult.success(service.adminAdvice(prompt));
    }
}
```

权限不能只依赖前端按钮隐藏，后端接口再次校验角色，防止用户直接构造请求访问不属于自己的 AI 场景。

### 3. Prompt 场景封装

文件：`src/main/java/com/library/service/impl/AIServiceImpl.java`

```java
@Service
public class AIServiceImpl implements AIService {
    private final DeepSeekClient client;

    public AIServiceImpl(DeepSeekClient client) {
        this.client = client;
    }

    public String readerRecommend(String prompt) {
        return client.chat(
                "你是图书馆推荐助手，请根据读者需求推荐图书并说明理由："
                        + prompt);
    }

    public String adminAdvice(String prompt) {
        return client.chat(
                "你是图书馆运营顾问，请分析库存和运营问题并给出可执行建议："
                        + prompt);
    }
}
```

业务层将用户输入包装成不同的角色提示词，使同一个模型客户端服务于两种业务场景。

### 4. DeepSeek 客户端调用

文件：`src/main/java/com/library/common/util/DeepSeekClient.java`

```java
public String chat(String prompt) {
    if (apiKey == null || apiKey.isBlank()) {
        return "AI 服务未配置，请设置 DEEPSEEK_API_KEY 环境变量";
    }

    try {
        String body = mapper.writeValueAsString(Map.of(
                "model", model,
                "messages", List.of(Map.of(
                        "role", "user",
                        "content", prompt)),
                "stream", false));

        HttpRequest request = HttpRequest.newBuilder(URI.create(endpoint))
                .timeout(Duration.ofSeconds(10))
                .header("Authorization", "Bearer " + apiKey)
                .header("Content-Type", "application/json")
                .POST(HttpRequest.BodyPublishers.ofString(body))
                .build();

        JsonNode root = mapper.readTree(
                client.send(request, HttpResponse.BodyHandlers.ofString()).body());
        return root.path("choices").path(0)
                .path("message").path("content").asText();
    } catch (Exception e) {
        log.warn("DeepSeek request failed", e);
        return "AI 服务暂时不可用，请稍后重试";
    }
}
```

调用流程为：页面输入问题 → 后端角色鉴权 → Service 组装 Prompt → HTTP 请求模型服务 → 解析 `choices[0].message.content` → 返回统一接口结果。

## 四、AI 功能运行注意事项

当前项目默认连接 `https://api.deepseek.com/chat/completions`，配置位于 `src/main/resources/application.yml` 和本地覆盖文件 `config/application-local.yml`。

```yaml
deepseek:
  api-key: ${DEEPSEEK_API_KEY:}
  endpoint: ${DEEPSEEK_ENDPOINT:https://api.deepseek.com/chat/completions}
  model: ${DEEPSEEK_MODEL:deepseek-chat}
  timeout-ms: ${DEEPSEEK_TIMEOUT_MS:10000}
```

如果部署服务器无法访问 `api.deepseek.com`，页面会出现 `timeout of 10000ms exceeded`。答辩展示时可以说明：AI 模块采用可配置的 OpenAI 兼容 HTTP 接口，实际部署需要保证服务器网络、API Key 和模型服务可用；也可以将 endpoint 切换到其他兼容服务或本地模型网关。

另外，API Key 不应提交到 Git 仓库，建议只使用环境变量配置，并在密钥泄露后立即撤销和重新生成。

## 

1. 统计分析通过 MyBatis 聚合查询按分类汇总图书数量、总库存和可借库存。
2. 统计接口只允许管理员访问，前端使用百分比和指标卡进行可视化展示。
3. AI 页面根据用户角色选择推荐或运营建议场景，后端再次进行权限校验。
4. AI 客户端封装了请求组装、鉴权、响应解析和异常降级，便于后续替换模型服务。
5. 当前 AI 超时的根本前提是后端必须能访问模型 API；网络不可达时需要代理、可访问的部署环境或本地模型。
